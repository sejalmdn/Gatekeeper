# Gatekeeper: datasets and scenarios

## Dataset organization

A dataset release may contain multiple scenario types. Store the type on every scenario so its
input contract and applicable rules remain explicit.

| Scenario type | Phase | Input | Evaluation focus |
|---|---:|---|---|
| `single_turn` | 1 | One user message | One resulting response |
| `multi_turn` | 1 | Supplied history plus one new message | One response using that context |
| `tool_use` | 1 | Message and optional history | Requested tool selection and arguments |
| `agentic_task` | 3 | Goal, optional history, and fixture | Workflow behavior and final outcome |

Phase 1 excludes adaptive conversation simulation. A single-turn or multi-turn application may make
internal model calls, but the scenario evaluates the requested final response. A `tool_use` scenario
tests the model's requested call; it does not certify actual tool execution or result handling.

## Common structure

```text
Dataset release
- identity, name, version, application target
- default rule bindings
- scenarios[]

Scenario
- identity, name, scenario type
- typed input
- expected values
- scenario-specific rule bindings
```

Keep the scenario definition separate from evidence generated by each attempt. A run stores exact
dataset, candidate, rule, threshold, severity, and repeated-run versions or snapshots.

## Illustrative inputs

```json
{"type": "single_turn", "input": {"user_message": "What is 2 + 2?"}}
```

```json
{
  "type": "multi_turn",
  "input": {
    "history": [
      {"role": "user", "content": "My order is 123."},
      {"role": "assistant", "content": "How can I help with it?"}
    ],
    "user_message": "Where is it?"
  }
}
```

```json
{
  "type": "tool_use",
  "input": {"user_message": "Where is order 123?"},
  "expected": {"tool": "lookup_order", "arguments": {"order_id": "123"}}
}
```

Expected values remain private to Gatekeeper. Rule bindings may reference them rather than duplicate
them. Dataset-level rules must declare applicable scenario types or evidence requirements.

The Phase 3 `agentic_task` schema will add setup fixtures, outcome expectations, and trace evidence
requirements when that phase is designed.
