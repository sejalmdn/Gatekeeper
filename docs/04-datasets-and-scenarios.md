# Gatekeeper: datasets and scenarios

## Dataset organization

Developers upload scenarios into immutable datasets for evaluation. A dataset may contain multiple
scenario types. Store the type on every scenario so its input contract and applicable rules remain
explicit.

| Scenario type | Phase | Input | Evaluation focus |
|---|---:|---|---|
| `single_turn` | 1 | One user message | One resulting response |
| `multi_turn` | 1 | Supplied history plus one new message | One response using that context |
| `tool_use` | 1 | Message and optional history | Requested tool selection and arguments |
| `agentic_task` | 3 | Goal, optional history, and fixture | Workflow behavior and final outcome |

Phase 1 excludes adaptive conversation simulation. A configured agent may make internal model calls,
but the scenario evaluates the requested final response. A `tool_use` scenario tests the target's
requested call; it does not certify actual tool execution or result handling.

## Common structure

```text
Dataset
- identity and name
- default rule bindings
- scenarios[]

Scenario
- identity, name, scenario type
- typed input
- scenario-specific rule bindings
```

Keep the developer-supplied scenario definition separate from evidence generated by each backend
invocation. Expected values remain private inside rule bindings and never enter the candidate
request.

## Illustrative inputs

```json
{"scenario_type": "single_turn", "input": {"user_message": "What is 2 + 2?"}}
```

```json
{
  "scenario_type": "multi_turn",
  "input": {
    "history": [
      {"role": "user", "content": "My order is 123."},
      {"role": "assistant", "content": "How can I help with it?"}
    ],
    "user_message": "Where is it?"
  }
}
```

```json
{
  "scenario_type": "tool_use",
  "input": {"history": [], "user_message": "Where is order 123?"}
}
```

Phase 1 messages contain text only and use `user` or `assistant` roles. Multi-turn history must
contain at least one message. Tool-use history is optional and defaults to an empty list. System
prompts and exposed tool definitions belong to the candidate, not the scenario. Dataset-level rules
declare applicable scenario types; scenario rules apply only to their referenced scenario.

The Phase 3 `agentic_task` schema will add setup fixtures, outcome expectations, and trace evidence
requirements when that phase is designed.
